Task: Investigate and Fix Recovery Logic Consistency (Minimal, Targeted Changes Only)

The AI Bot is already tested, functional, and stable. This is not a request to redesign or refactor the trading engine. The objective is to identify why the recovery logic behaves differently in certain real-trade scenarios and make the smallest possible changes to restore consistent behavior.

Scope

Keep changes strictly limited to the recovery execution path. Do not perform unnecessary refactoring or architecture changes.

The goal is to preserve all existing functionality while ensuring recovery behaves consistently across all AI Bots.

Current Expected Behavior

Each AI Bot has its own entry strategy, but once a qualifying loss occurs, they should all use the same shared recovery logic.

The intended flow is:

Bot executes its own strategy.
If the trade wins, continue with the normal strategy.
If the trade loses, enter the shared recovery engine.
Recovery follows the existing logic (OVER 5 / UNDER 4 as already implemented).
Once recovery succeeds, control returns to the bot's original strategy.

The recovery logic already works correctly in UNDER 8 and OVER 1 and should be treated as the reference implementation.

Problem

Runtime logs showed that MATCHES and particularly DIFFERS sometimes recover differently during real trading, even though the bot itself is otherwise working correctly.

This appears to be an execution inconsistency rather than a strategy issue.

Required Investigation

Audit only the relevant execution path:

strategy signal
trade request
purchase confirmation
contract monitoring
settlement
recovery trigger
recovery execution
recovery completion
return to normal strategy

Determine exactly why DIFFERS (and MATCHES if affected) diverges from the recovery behavior used by UNDER 8 and OVER 1.

Possible causes include:

asynchronous timing
race conditions
duplicate contract events
stale state
incorrect settlement handling
different execution branches
recovery state reset issues
virtual vs real trade differences

Do not guess. Identify the actual root cause from the code.

Required Fix

Do not change the DIFFERS entry strategy.

The only required behavioral change is:

Keep DIFFERS trade-entry logic exactly as it is.
When a DIFFERS trade loses, it should enter the same shared RecoveryStrategyEngine already used by UNDER 8 and OVER 1.
Reuse the existing recovery implementation rather than creating a separate one.
Preserve the current recovery rules, progression, stake logic, reset behavior, TP/SL, and execution flow.

The only difference between bots should be how they enter trades. Once recovery is required, every bot should follow the same recovery pipeline.

Stability Requirements

Ensure:

exactly one recovery decision per settled contract
no duplicate recovery triggers
no skipped recovery
deterministic recovery state
smooth execution from:
strategy → purchase → settlement → recovery → return to strategy

Do not introduce regressions into any existing AI Bot.

Verification

Confirm that:

UNDER 8 behaves exactly as before.
OVER 1 behaves exactly as before.
DIFFERS keeps its existing entry logic.
A winning DIFFERS trade continues normally.
A losing DIFFERS trade enters the same shared recovery flow used by UNDER 8 and OVER 1.
MATCHES also uses the correct recovery path if applicable.
Virtual and real trading now produce identical recovery decisions.
Deliverables

Provide:

The root cause of the inconsistent recovery behavior.
The files modified.
A brief explanation of why the fix is safe.
Confirmation that only minimal, targeted changes were made.
Confirmation that the shared recovery logic was not redesigned, only consistently applied.
Push the approved changes to the GitHub repository.
