# Refactor Virtual Hook into a Shared Runtime Service

The Virtual Hook implementation is working, but before we build the Exit Digit History engine, I want to refactor its architecture.

The goal is to make Virtual Hook a **shared runtime service**, not logic owned by the Trade Parameters block.

After completing the refactor, commit the changes and push them to the current GitHub branch.

---

# Objective

Separate:

* **Configuration** (Blockly)
* **Runtime State** (Trade Engine)

The Blockly blocks should only configure Virtual Hook.

The Trade Engine should own and manage the Virtual Hook lifecycle.

---

# 1. Trade Parameters = Configuration Only

The **Trade Parameters** block should only provide the initial configuration.

It should define:

* Virtual Hook Enabled (default)
* Number of Virtual Trades
* Number of Real Wins before reset

After initialization, the Trade Parameters block should not control the runtime.

Its job ends after the bot starts.

---

# 2. Create a Shared Runtime Service

Create a dedicated runtime module, for example:

```text
services/tradeEngine/runtime/VirtualHookRuntime.js
```

(or an equivalent location that matches the current architecture).

This runtime service becomes the single source of truth.

It should maintain:

* virtualHookEnabled
* virtualMode
* virtualTradeCounter
* realWinCounter
* virtualTradeLimit
* realWinLimit
* virtualHistory (future use)
* lastVirtualResult
* currentPhase

No duplicate state should exist elsewhere.

---

# 3. Runtime API

Expose methods such as:

* enableVirtualHook()
* disableVirtualHook()
* configureVirtualHook()
* enterVirtualMode()
* enterRealMode()
* onVirtualTradeComplete()
* onRealTradeComplete()
* resetVirtualHook()
* getVirtualHookStatus()
* isVirtualMode()

Every Blockly block should communicate through this runtime service.

---

# 4. Engine Integration

The execution engine should no longer read values directly from the Trade Parameters block after startup.

Instead:

Purchase

↓

Proposal

↓

Open Contract

↓

Settlement

↓

VirtualHookRuntime

↓

Next State

All Virtual Hook decisions should come from the runtime service.

---

# 5. Existing Blocks

Update all existing Virtual Hook blocks to use the runtime service.

This includes:

* Virtual Hook Settings
* Virtual Hook Enable/Disable
* Virtual Hook Status

They should not maintain independent state.

---

# 6. Future Compatibility

Design the runtime so future systems can reuse it directly.

Examples:

* Exit Digit History Engine
* Recovery Engine
* AI Strategy Engine
* Statistics Engine
* Analytics Blocks

These systems should simply call the Virtual Hook runtime instead of implementing their own tracking.

---

# 7. Backward Compatibility

Do not change XML compatibility.

Existing bots should continue working exactly as before.

The only change should be the internal architecture.

---

# 8. Code Quality

During the refactor:

* Remove duplicated Virtual Hook state.
* Remove duplicated counters.
* Keep one source of truth.
* Do not introduce circular dependencies.
* Keep runtime logic independent from Blockly UI.

---

# 9. Verification

After completing the refactor, verify:

* Virtual mode still works.
* Real mode still works.
* Switching between modes still works.
* Existing XML bots behave identically.
* Contract Switcher still works.
* Symbol Changer still works.
* Prediction Setter still works.

Ensure all features continue working after the refactor.

---

# 10. Git

When the refactor passes compilation and verification:

* Commit the changes with a clear message, for example:

```
Refactor Virtual Hook into shared runtime service
```

* Push the changes to the current GitHub branch.

Do not leave the implementation partially completed. Ensure the repository is left in a clean, buildable state before pushing.
