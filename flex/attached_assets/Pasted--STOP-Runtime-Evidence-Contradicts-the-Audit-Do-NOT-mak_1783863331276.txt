# This Contradiction Must Be Resolved First

The previous audit stated:

* `__pending__` no longer exists at runtime.

Yet the runtime clearly shows:

```
Restoring from ASM state — loginid: __pending__
```

followed by

```
accountId (ASM): __pending__
```

which directly causes

```
POST /options/accounts/__pending__/otp
```

and later

```
account_id: __pending__
```

inside the authorize request.

Those logs prove that **`__pending__` still exists in the runtime authentication state.**
